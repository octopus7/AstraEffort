# Texture pass design and interpretation

This pass retains Alder Pass geometry, layout, lighting and camera settings. It changes UV0 and surface materials only. Five independent built-in ImageGen calls produced timber, stone, bark, conifer foliage and brushed-metal grayscale detail sources. Raw 1254 × 1254 PNGs are preserved, including prompts, timestamps and hashes. Although the prompts requested 2048 pixels, the actual returned size is used in all calculations.

Each authored polygon receives a separate UV island. Its planar projection is area-normalized to 128 base texels per world metre, then placed in a unique rectangular allocation with at least 8 effective texels of padding on each side. The final rule is `max(8, virtual_atlas_side / 1024)` per side: 44 meshes use 8, two use 16, and Terrain uses 32. Curved/non-planar face distortion, triangle edge stretch, tiny triangles and small numerical UV intersections are reported explicitly. Geometry hashes before/after UV assignment must match.

The first fresh UE checks exposed unwanted chart welding: source polygon 201 had U=4213.0049 pixels, but UE used polygon 200's U=4196.0313 at their shared world vertex. Blender-to-FBX roundtrip retained the correct source UV. Installed UE `Runtime/Engine/Public/MeshBuild.h:61` defines `UVsEqual` with 1/1024 tolerance; `Developer/MeshBuilder/Private/StaticMeshBuilder.cpp:1541` uses it to merge render vertices. With a 32768 coordinate atlas this is 32 effective pixels, exceeding the original 16-pixel gap. The final larger gaps exceed this normalized tolerance without changing the geometry or sampling density. Failed attempts and diagnostic coordinates remain as evidence.

The 512–32768 virtual atlas side lengths are coordinate scales, not allocated giant textures. Each material instance samples an independently generated repeating detail image with UV multiplier `virtual_atlas_side / actual_image_size`. Consequently actual base texture sampling remains 128 texels/m while the normalized mesh charts remain unique. Repeated source texels are intentional; this is not a uniquely hand-painted color atlas or a claim that every surface owns different source pixels. Padding is validated in that effective base-texel coordinate system.

Image sources are applied through Base Color and Roughness. Existing palette tint, silhouettes, roof/track proportions and restrained style remain. Lettering, clock markings, smooth stylized glass, emissive lamp glass and dark tunnel backing retain solid/special materials. Their geometric UV measurements are reported, but a rendered image texel density is not claimed for those exceptions. Very small bevels and lettering triangles can cover less than one base texel; they are not silently enlarged to break density consistency. This face-chart approach trades extra seams/split vertices for predictable, measurable scale.

The generated NPOT images are used at their actual 1254-pixel size, without resizing or fake upsampling claims. UE textures use Wrap addressing, linear data, no mipmaps and NeverStream. This preserves the audited base level, but is a limitation for large production scenes and can increase distant texture aliasing compared with a production mipmapped texture pipeline. No displacement or physical surface-relief simulation is claimed.

Fresh-process validation reads every placed owned LOD0 triangle from UE, transforms actual vertices to world metres, reads actual imported UV0 and resolves actual material texture dimensions/scales. It checks source/UE area agreement, density percentiles, tiny-face exceptions, atlas containment/padding, within-chart intersections, all material bindings, unchanged actor transforms and recursive package isolation. Gameplay checks use the real possessed DefaultPawn, its own movement HitResult, clear starts and positive travel. Actual comparison renders use exactly the first-delivery cameras and 1920 × 1080 settings. FirstDelivery is immutable.
