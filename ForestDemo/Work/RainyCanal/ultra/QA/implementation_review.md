## Findings sent to the implementer

1. **P1 — Textured surfaces compile to the default material.** `Execution/build5.log:2071` and subsequent diagnostics through line 2387 report that the ten textured material families and Ground fail PCD3D_SM5 compilation because their roughness samples use Linear Color instead of Linear Grayscale. The first renders visibly show uniform grey/brown architecture, ground and vegetation. The source selects LINEAR_COLOR for all non-sRGB non-normal textures while importing roughness as TC_GRAYSCALE. Correct the sampler and verify in a fresh process; a connected graph is not proof of successful compilation.
2. **P2 — Overcast readability and lamp color are incorrect in the first draft.** Large facades and vegetation backs are almost black, hard sunlight shadows dominate, and lamps illuminate large cold blue pools. Cream/sage/rose and stone/timber differences cannot be assessed while fallback is active. The implementer has identified sky capture setup and positional FColor arguments as relevant corrections. Reinspect new renders after those changes.
3. **P2 — Dock approach is obstructed by the raised quay cap.** `Draft/dock.png` shows the cap crossing the opening and a disconnected-looking step/deck transition. Source confirms cap exclusion only around bridges, not the dock. Correct the opening and verify continuous contact/collision from street to dock. The implementer has acknowledged this defect and is revising the ramp.
4. **P2 — Door approaches need paved continuity.** The quay mask ends at |x|=15 m; canal-facing building stoops extend toward the canal only to |x|≈15.82 m for buildings placed at |x|=20 m. Most front doors therefore have a gap to the paved quay. This is a source-based finding pending color-correct renders. Add appropriate short approaches or document the intended grassy access.
5. **P2 — Existing validation would overstate coverage if treated as a whole-scene pass.** Material graph checks inspect only Rain/CanalWater/PuddleWater connections and do not detect the textured-material compiler failures. Whole-image time-pair pixel changes cannot independently establish water motion because animated rain appears throughout the frame. Add a fresh shader-log gate and independent visual/effect evidence.
6. **P2 — Walking behavior is not yet proved.** The current runtime code uses a DefaultPawn/free-fly swept path over the stone bridge, checks only its X progress, and does not exercise walking step/slope behavior, timber bridge travel, or dock access. The source comment correctly says this is not a walking-character claim. Final reporting must preserve that limitation unless stronger runtime evidence is added.
7. **P3 — Capture and density details.** The first overview crops the nearest boundary corner and top-down has almost no footprint margin. The rainy-street puddle is cropped to a bottom sliver; its rings cannot be assessed. A dedicated puddle time pair is recommended. Tree/shrub/grass placement scales alter the nominal 128 px/m density, so actual placed-scale exceptions need recording.
